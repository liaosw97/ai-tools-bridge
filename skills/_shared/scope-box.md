## 工作量盒、预估告知与升轨保险丝

轻轨（hotfix/quick）的边界控制机制。**所有升降轨判定使用可机械判定的代理指标**（轮次/文件数/场景数），不使用分钟数作为判定条件。分钟数仅用于预估告知与卡片事后记录。

---

### 1. 预估告知（仅告知，不判定）

开始执行前，根据现象先给出预估：

> "预期约 X 分钟（改动 ≤2 源文件 + 回归测试）"

预估基于改动量估算，不设计时器、不作为流程判定依据。

### 2. 工作量盒（判定用代理指标）

| 轨道 | 盒边界 | 配置键（openspec/config.yaml limits，未配置用默认值） |
|------|--------|------|
| hotfix | 改动 ≤ 2 个源文件 + 回归/新增测试 ≤ 3 个场景 | `hotfix-locate-rounds: 3`（定位尝试轮数）、`hotfix-max-files: 2`、`hotfix-max-scenarios: 3` |
| quick | 改动 ≤ 3 个源文件 | `quick-max-files: 3` |

**盒与 limits 冲突取严**：limits 配置的盒边界与默认盒边界不一致时，以先达到者为准（取严），不因配置宽松而突破默认质量边界。

### 3. 升轨保险丝

**盒满即停**：改动将超过工作量盒（>2 源文件 或 >3 场景）时：

1. 暂停，输出"超出轻轨边界"提示
2. **升轨前先把已定位的根因/方案落盘到 hotfix.md 卡片**（避免 /clear 后根因丢失）
3. 保留已有产物
4. 给出选项：
   - ① 继续硬做（附风险）
   - ② 升轨 /sdd-propose（单一 commit 约束豁免，已改部分可先提交）
   - ③ 先提交已改部分
5. 用户选择升轨后，已生成内容不丢失且引导到标准路径

**不可 hotfix 的信号**（命中任一即拒绝并引导升轨）：

- 修改公共接口签名
- 跨 2+ 模块
- 需要数据迁移
- 需要设计决策（有 2+ 候选方案）
- 需求描述含"架构""重构""迁移"等关键词

### 4. 定位尝试轮次上限

hotfix 定位阶段：复现 → 二分定位根因。尝试达到 N 轮（默认 3，`limits.hotfix-locate-rounds` 可配置）仍未定位根因时，提示升轨而非无限排查。

### 5. 预估/实际时间记录（事后）

卡片中的"预估/实际: X min"字段仅为事后追溯记录，不作为流程判定依据。
