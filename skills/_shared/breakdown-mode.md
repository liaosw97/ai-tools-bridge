### 0.5 拆分模式检测

检测用户输入或命令参数是否触发拆分模式：

**参数触发**：
- 命令包含 `--breakdown` 或 `-b` 参数
- 检测到参数后设置 `breakdown_mode = true`

**自然语言触发**：
- 用户需求描述包含触发关键词："拆分"、"分层"、"逐步探索"、"功能模块"
- 检测到关键词后设置 `breakdown_mode = true`

**不触发拆分模式**：
- 需求简单明确，无需分层探索
- 用户明确表示"不拆分"、"直接探索"

**配置覆盖**：
- 读取 `openspec/config.yaml` 的 `breakdown.enabled` 配置（默认 true）
- 配置为 false 时，即使触发关键词也不进入拆分模式

### 拆分模式交互流程

当 `breakdown_mode = true` 时，执行以下交互流程：

**1. L1 功能模块拆分**
- AI 分析需求，提议功能模块列表
- 输出格式：
  ```
  功能模块列表（L1）：
  1. [模块A名称] — [简述]
  2. [模块B名称] — [简述]
  ...
  ```
- 询问用户："请确认或调整功能模块列表"
- 用户确认后记录：`L1 = [模块A, 模块B, ...]`

**2. L2 功能单元拆分**
- 对每个 L1 模块：
  a. AI 提议该模块的功能单元列表
  b. 输出格式：
     ```
     [模块名] 功能单元列表（L2）：
     1. [单元A名称] — [简述]
     2. [单元B名称] — [简述]
     ...
     ```
  c. 用户确认或调整
  d. **即时追问**：对每个功能单元追问细节
     - 输出："关于 [单元名]，请补充以下信息："
     - 根据单元类型生成追问问题（如："需要哪些字段？"、"是否需要筛选？"）
  e. 记录：`L2[模块] = [单元A, 单元B, ...]`
  f. **细化**：对每个功能单元进行细化，确保粒度适中

**3. L3 功能点拆分（可选）**
- AI 判断功能单元是否需要继续拆分
- 判断标准：功能单元包含 >3 个独立操作（可独立触发和验证的用户交互）
- 如需拆分：
  - 询问用户："功能单元 [X] 包含多个独立操作，是否继续拆分？"
  - 提供选项：
    - ① 继续拆分 → AI 提议 L3 功能点列表并追问细节
    - ② 停止拆分 → 以当前 L2 单元为叶子节点
    - ③ 跳过此单元 → 不生成该单元的任务
- 如不需拆分：
  - 输出："功能单元 [X] 粒度适中，无需继续拆分"
  - 用户可选择强制拆分或确认停止

**4. 目录冲突检测**
- 拆分过程中，如发现项目中已存在与当前功能相似的目录
- 相似度阈值：>60%（名称关键词 Jaccard 相似度）
- 暂停并输出：
  ```
  ⚠️ 检测到可能已存在的功能模块：
  - [目录A路径] — [相似度描述]
  - [目录B路径] — [相似度描述]

  是扩展现有模块还是新建独立模块？
  ```
- 用户提供选择后继续

**5. 产出功能树**
- 将功能树写入 brainstorm.md 的 "## 功能拆分" 节
- 格式见后置逻辑"功能树产出"节

### 异常流处理

**用户中途取消**：
- 用户输入"取消"、"停止"或类似意图
- 输出：
  ```
  已取消拆分。当前已完成：
  - L1: [已确认的模块列表]
  - L2: [已确认的单元列表]

  请选择：
  ① 保存当前状态并退出（后续可继续）
  ② 丢弃本次拆分，回到正常 brainstorm 流程
  ```

**需求矛盾或无法拆分**：
- AI 检测到需求描述存在矛盾或功能模块无法拆分为独立单元
- 暂停并输出：
  ```
  ⚠️ 发现问题：[矛盾点或阻塞原因]

  请澄清需求或调整拆分策略。
  ```
- 用户澄清后继续
