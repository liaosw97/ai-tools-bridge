## hotfix 调试认知模型

hotfix 轨道面向"改 bug / 细小改动"。认知模型是**调试**而非规格：先定位根因，再最小修复。产物收敛到 1 份 hotfix.md 卡片，不生成 proposal/spec/tasks。

---

### 1. 定位流程

1. **复现** — 确认能稳定复现（无法复现 → 记录现象与已尝试步骤到卡片，标注"未复现"）
2. **二分定位** — 通过系统化排查缩小范围，定位根因（含 文件:行）
3. **轮次上限** — 尝试达 N 轮（默认 3，`limits.hotfix-locate-rounds` 可配置）仍未定位 → 提示升轨（见 scope-box.md §4）

定位不猜测、不盲目重试（遵循 systematic-debugging 纪律的精简版）。

### 2. 修复原则

- **根因陈述**：动手前先向用户陈述根因 + 最小改动方案，一行确认后动手
- **最小改动**：只改必要的代码，不做无关重构
- **影响范围**：明确改动触碰了哪些既有行为

### 3. 测试与提交

- **TDD 紧凑循环**：补/跑回归测试（先写失败测试 → 最小修复 → 测试通过）
- **单一 commit**：message 前缀 `hotfix(<name>):`（升轨路径豁免，见 scope-box.md §3 选项②）

### 4. 卡片即终态

- 完成后写入 hotfix.md 卡片（现象/根因/修复/验证/衍生）
- 卡片是 hotfix change 的唯一产物，不进依赖链
- 生命周期：ship 走轻量归档豁免；continue/ff/verify 检测到 hotfix change 时降级引导，不强行补齐产物
